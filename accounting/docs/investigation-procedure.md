# データソース調査手順(Dropbox・Googleスプレッドシート共通)

新しい店舗、または既存店舗の新しい年度・月を対象に追加する際の、実データ確認手順です。数値そのものではなく「どこに何があるか」を確認するための手順なので、このファイルはGit管理対象とします。

## 1. Dropbox側(日報)の調査手順

1. `mcp__Dropbox__search` で店舗名(例:「守山店」)をキーワード検索し、関連フォルダの候補を洗い出す。
   - `search_mode: "title_only"` を使うと、ファイル内容ではなくファイル名・フォルダ名のみに絞れるため、まずはこちらでフォルダ構成を把握する。
2. 候補の中から「日報」「集計」「月報」などの語を含むフォルダに絞り込み、`mcp__Dropbox__list_folder`(`recursive: false`)でそのフォルダの直下を一覧表示する。
3. 年度フォルダ(例:「2026年度」)→「システム最新（◯◯店）」のような構成になっている場合が多い。最新年度フォルダの中身を確認し、月ごとのファイル(例:「①8月.xlsx」)を特定する。
   - 同名に近いファイルが複数の場所に存在することがある(過去の集計表、個人のダウンロードフォルダ内の控えなど)。`server_modified` / `client_modified` の日付が直近で、かつ共有フォルダ配下にあるものを正とみなす。ただし最終判断はオーナー確認を優先する。
4. 対象ファイルが1MB超の場合、`mcp__Dropbox__fetch` の結果はテキストファイルとして保存される。保存されたファイルは1行の巨大なJSONになりやすいため、`python3 -c "import json; ..."` 等でパースし、タブ区切りの行として整形してから内容を確認する。
5. シート名(タブ名)の見分け方: Dropbox側のExcel抽出結果には明確な区切り記号がないため、「タブ文字を含まない短い行」を機械的に抽出すると、シート名らしき行が浮かび上がる。日付だけの数字行(`1`〜`31`)は日別シートの可能性が高い。

## 2. Googleスプレッドシート側(転記先)の調査手順

1. `mcp__Google_Drive__search_files` で `title contains '<ファイル名の一部>'` を指定して検索し、`fileId` を取得する。
2. `mcp__Google_Drive__read_file_content` で内容を取得する。大きいファイルは同様にテキストファイルに保存されるため、Bashでパースする。
3. シート(タブ)の区切りが本文中に明示されない場合があるため、見出しになりそうな文字列(店舗名、月名など)で検索し、前後の文脈からシート構成・列構成を特定する。
4. マージセルは `\[merged\]` として出力されるため、見出し行とデータ行の対応を取るときはこの表記に注意する。

## 3. 共通の注意点

- どの調査でも「読み取りのみ」。書き込み系ツール(`create_file` / `update_file` / `move` など)は、承認を得るまで使用しない。
- ファイル名・シート名・列構成は店舗や年度によって変わることがあるため、他店舗・他月に展開する際も、このファイルの手順で毎回実地確認してから `config/stores.yaml` を更新する。値を過去の実績から類推して埋めない。
- 実売上・目標値などの実データや、調査で得た具体的な数値は、このファイル(Git管理対象)には書かない。`accounting/output/` 配下(Git管理対象外)に記録する。
